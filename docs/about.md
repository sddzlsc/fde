## 为什么做这件事

FDE（Forward Deployed Engineer，前沿部署工程师）正在成为 AI 落地中最关键的岗位之一。但在中文互联网上，关于它的内容大致分为三类：

- 招聘 JD 的翻译和复述；
- 几家明星公司的传奇故事；
- 「AI 时代最火岗位」的焦虑营销。

这些内容并非没有价值，但它们很少回答一个零基础读者真正关心的问题：

> **我没做过 FDE，甚至不是工程师，应该从哪里开始？**

这本指南试图补上这一层：把 FDE 的工作拆成可以学习、可以练习、可以被验证的动作。它不承诺速成，也不把某家公司的做法当成唯一答案。

## 内容原则

### 1. 双源优先，单源标注

能交叉验证的事实，至少给两个来源；只有一个来源的，明确写「单一来源」「据报道」「待核」。公司披露、第三方估算、媒体转述不混用。

### 2. 区分「事实」与「判断」

- 事实：某公司披露的收入、某个客户案例的指标、某份报告的方法；
- 判断：这些事实意味着什么、适不适合你、下一步该怎么做。

判断可以有争议，事实不能编造。

### 3. 不把案例当模板

案例是证据，不是答案。Palantir 的做法、OpenAI 的团队配置、Harvey 的定价，都有其特定条件。我们会写「可迁移的经验」，也会写「不适用的边界」。

### 4. 承认不知道

有些来源被拦截，有些数据只有二手转述，有些细节无法核实。遇到这些情况，我们选择标注「待核」或直接不写，而不是用模糊表述蒙混过去。

### 5. 对读者诚实

这本指南不会告诉你「读完就能年薪百万」，也不会假装 FDE 适合所有人。它会告诉你：这份工作的难点在哪、需要补什么、什么情况下你可能会失败。

## 它是怎么写的

- **结构**：四个部分（认识、能力、现场、职业），10 章，3 个 Lab，5 个案例页，5 个附录。
- **写作**：中文简体，第二人称，尽量用具体动作替代抽象概念。
- **案例**：来自公开报道、公司披露、行业报告和从业者访谈；合成场景会明确标注。
- **审校**：事实、数据、来源经过多轮交叉检查；仍有错误，欢迎在 GitHub 纠错。
- **工具**：内容使用 Markdown 编写，站点由 VitePress 构建，部署在 GitHub Pages。
- **AI 辅助**：资料整理与初稿阶段使用了 AI 辅助，所有事实均要求按来源复核。发现错误，请直接提 issue。

## 它的边界

这本指南**不是**：

- 一份官方职业认证标准；
- 一份投资、采购、法律或薪酬建议；
- 对任何公司、产品或个人的背书；
- 对 FDE 岗位的完整覆盖（不同公司、行业差异极大）。

它**是**：

- 一个帮助你建立地图、开始行动的起点；
- 一套可以复用的方法、模板和练习；
- 一个持续更新的开源项目。

## 维护与贡献

这个项目由社区维护，发起人是 [@sddzlsc](https://github.com/sddzlsc)。欢迎：

- 纠错：事实、数据、来源、错别字、失效链接；
- 补案例：真实、可公开、有出处的 FDE / AI 落地案例；
- 改进方法：模板、练习、Lab、面试题；
- 翻译：把核心章节翻译成其他语言。
