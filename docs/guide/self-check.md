# FDE 自评：你现在在哪一格

<div class="chapter-meta">
  <span><strong>题量</strong> 20 题</span>
  <span><strong>用时</strong> 5-8 分钟</span>
  <span><strong>结果</strong> 四维分数 + 下一步建议</span>
</div>

> 这不是考试，也不是招聘测评。它只做一件事：帮你把「我觉得自己还差很多」变成「我知道下一步补哪一块」。

## 怎么打分

按**最近 12 个月的真实行为**打分，不按「我大概知道」或「我以后应该会」打分。

| 分数 | 含义 | 例子 |
| --- | --- | --- |
| 0 | 没做过 | 没写过 SQL |
| 1 | 知道概念 | 知道 SQL 是查数据库的，但没写过 |
| 2 | 指导下做过 | 跟着教程或同事做过一次 |
| 3 | 独立做过 | 不看教程也能完成，遇到过问题并解决 |
| 4 | 能教别人 | 能给别人讲清楚，并能处理异常情况 |

如果你在两个分数之间犹豫，选低的那个。自评的目的是找差距，不是给自己发奖。

## 怎么读结果

四个维度不是「越高越好」的线性排名，而是四种不同的能力：

- **工程力**：你能不能独立把东西跑起来、排障、上线。它是 FDE 的底盘。
- **业务力**：你能不能找到真问题、算清价值、说服干系人。它决定你做的事值不值得。
- **产品力**：你能不能把一次解法抽象成可复用能力。它决定你是「项目工人」还是「产品贡献者」。
- **现场力**：你能不能在模糊、冲突、变化的环境里推进事情。它决定你能不能活下来。

一个常见的误区是：**只补最弱的那一维**。更有效的策略通常是：

1. 先把工程力补到「能独立做出原型」（至少 10/20）；
2. 再把业务力补到「能独立完成一次访谈和 ROI 测算」（至少 12/20）；
3. 产品力和现场力，在真实项目中边做边补。

如果你某一维已经很高，不要急着刷到满分。FDE 的稀缺性来自「组合」，不是单项冠军。

## 四个分数段

### 0-20 分：起点

你不需要立刻成为工程师。先读第 1、2 章，建立概念；然后完成第 4 章的「必会 20 个动作」里最简单的 5 个：命令行、HTTP 请求、Git 提交、SQL 查询、看日志。

**下一步**：[12 周学习路线](./roadmap.md) → 第 1 章 → 第 4 章。

### 21-40 分：探索者

你已经有一定基础，但还没有完整跑过一次部署。不要继续囤课，直接做 [Lab A](/labs/lab-a-ticket-triage)：造数据、做基线、接 LLM、写评测。做完一次，比读十篇文章有用。

**下一步**：[Lab A](/labs/lab-a-ticket-triage) → 第 6 章 → 第 8 章。

### 41-60 分：准 FDE

你具备独立交付的雏形。现在最该做的不是「再学一个框架」，而是：

1. 选一个真实场景（哪怕很小），完整走一遍六阶段；
2. 把过程写成作品集，包含失败和反思；
3. 找 3 个做过 FDE 的人做信息访谈，校准自己的判断。

**下一步**：第 7 章 → 第 9 章 → 作品集。

### 61-80 分：现场型

你已经能独立负责部署。缺的往往不是知识，而是：

- 一个更复杂的场景（多系统、多干系人、合规约束）；
- 一个能为你背书的人；
- 一套可复用的方法论，而不是只靠个人经验。

**下一步**：第 8 章 → 第 10 章 → 带一个新人做项目。

## 一个提醒

分数低不代表你不适合做 FDE。很多优秀的 FDE 在转岗时，工程力只有 8/20，但业务力和现场力很强。他们靠的是：

- 知道自己不懂什么；
- 在关键节点找对人；
- 把每一次项目都变成可复用的经验。

相反，工程力满分但不愿意去现场、不愿意和用户说话的人，往往做不好 FDE。
