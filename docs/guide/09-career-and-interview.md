> 本章你会学到：如何判断自己适不适合做 FDE（Forward Deployed Engineer，前沿部署工程师）；用能力罗盘找到当前级别；在产品型、伙伴型、内部型三条路径里选一条；用 30/60/90 天计划补短板；把 3 个项目做成经得起追问的作品集；按 8 类面试题的框架准备第一轮面试。
>
> 一句话：FDE 的面试不考你知道多少，而考你有没有把一个模糊问题变成可验证结果的真实现场经历。

## 一个现场片段

（合成场景）

去年秋天，我们在一个开源社区做模拟面试，一下午三个人。

做了六年 Java 的后端讲了二十分钟分库分表。我们问：「客户为什么要上这个系统？」他愣了一下：「需求是产品给的。」

四年经验的咨询顾问讲了完整的行业分析和转型路线图，我们问：「原型跑过吗？」他说：「我们负责方案，实施由厂商做。」

三年经验的 SaaS 产品经理讲了 AI 助手的功能与增长指标，我们问：「上线后哪条业务指标变了、变了多少？」他说：「用户反馈还不错。」

三个人缺的其实是同一件东西：**一个自己从模糊问题走到真实指标的小项目**。三周后，产品经理先补上了——他用周末把公司内部流程做成能跑的原型，带着基线、评测集和三轮迭代来复盘。那一轮面试，面试官第一次追问了二十分钟，而且问得很细。那天的讨论比之前三个人加起来还长。

本章要帮你补的，就是这样一条能被验证、被追问的路径。

## 先判断：你适合做 FDE 吗

### 适合的人

- 看到「系统不好用」会忍不住动手改，而不只是吐槽。
- 愿意为结果负责：上线不算完，指标变了才算。
- 能忍受模糊：需求不清、数据脏、客户改主意是常态。
- 对业务好奇：愿意花半天跟客服坐在一起看真实工单。
- 能把问题拆小：客户说「全都要」时，切出第一周能验证的一块。

### 不适合的人

- 只想写代码、不愿见客户：FDE 可能有一半时间不在写代码。
- 只想做战略、不愿动手：FDE 的价值在现场交付里。
- 需要清晰边界和稳定作息：边界往往是你自己谈出来的。
- 把 FDE 当「高级驻场外包」：晋升靠产品反哺，不靠人天。
- 完全不愿出差：多数岗位有现场要求，面试时要问清比例。

### 五类转岗者：优势与短板

| 背景 | 天然优势 | 主要短板 | 最该补的动作 |
| --- | --- | --- | --- |
| 开发 | 工程实现、排障、系统设计 | 客户沟通、问题定义、价值翻译 | 独立完成 Lab A，访谈一个真实用户 |
| 咨询 / 实施 | 结构化表达、干系人管理、汇报 | 动手实现、评测、技术深度 | 把原型做到生产门槛，写出评测报告 |
| 售前 | 演示、需求挖掘、招投标 | 交付责任、生产化、失败复盘 | 接手一个试点到上线，全程背指标 |
| 产品 | 场景抽象、取舍、指标意识 | 工程细节、数据接入、排障 | 写代码跑通原型，自己排一次故障 |
| 运营 / 业务 | 业务细节、用户同理心、流程知识 | 技术底座、系统设计 | 完成 90 小时技术底座计划（见[第 4 章](./04-tech-foundations.md)） |

FDE 要的不是五边形战士，而是**有一维到主导级，其他维不低于独立级**。

## 能力罗盘：4 维 × 4 级

| 维度 | L1 跟随 | L2 独立 | L3 主导 | L4 定义 |
| --- | --- | --- | --- | --- |
| 工程力 | 按清单改代码、查日志、调通 API | 独立搭出可运行原型与评测脚本 | 主导生产化：权限、灰度、监控、回滚 | 定义工程标准与可复用平台能力 |
| 业务力 | 听懂业务词汇，复述现有流程 | 独立完成访谈、流程与数据地图 | 定义基线、价值指标与 ROI 口径 | 判断赛道与商业模式，影响客户决策 |
| 产品力 | 讲清一个功能解决谁的什么问题 | 把现场需求写成可评审的验收标准 | 设计可复用方案并反哺产品路线 | 定义产品方向与交付、定价模式 |
| 现场力 | 按脚本完成演示、记录与跟进 | 独立驻场，管理预期与冲突 | 主导多干系人项目，推动 Go/No-Go | 建立现场方法论、带教与复制团队 |

**怎么用**：每一格只认「最近 6 个月独立做过一次」的证据，不认「上过课、看过书」。

- 自评取四维中的最低值：L2 的门槛是「能独立交付一个模块」，不是「能独立讲一遍」。
- 下一阶段目标：至少一维上 L3，其余不低于 L2；面试官会沿你最强的一维深挖。
- 完整自评表见[能力自评](/guide/self-check)。

::: warning 反模式：把「跟随」当「独立」
跟着教程跑通 demo 是 L1；自己换数据、加评测、处理失败，才是 L2。虚报一级，三个追问就会露馅。
:::

## 三条路径：先选战场，再准备

| 路径 | 代表组织（据公开资料） | 你要证明什么 | 主要风险 | 准备什么 |
| --- | --- | --- | --- | --- |
| 产品型 | Palantir、OpenAI、Anthropic、Sierra、Decagon；中国的火山引擎 FDE 团队（据界面新闻等 2026-06 报道，B） | 能把现场发现抽象成平台能力 | 平台优先级与客户需求冲突 | 一份「现场需求 → 产品需求」的 PRD 样例 |
| 伙伴型 | Cognizant、埃森哲、麦肯锡、贝恩、凯捷；安永与火山引擎的千人级 FDE 团队（据中国日报网等 2026-07 报道，B） | 能在大组织里交付清楚、让客户续约 | 项目制思维、利润率压力、易变人天 | 一个多干系人项目的治理案例 |
| 内部型 | 企业自己的 AI 团队，例如得物公开分享的转型做法（据极客公园圆桌，C） | 能推动业务部门真正使用 | 组织惯性、预算归属、被当 IT 支持 | 一份内部推广计划与容错机制 |

路径不是终身标签。选路径看：**未来 18 个月，我能积累什么可迁移的证据。**

## 30 / 60 / 90 天计划

- **第 1-30 天：建底座，做出第一个作品。** 读完第 1-6 章；跑通 [Lab A](/labs/lab-a-ticket-triage) 第一版；做一次真实访谈；写下第一版一页纸。
- **第 31-60 天：把原型变成可验证的结果。** 补基线、评测集与指标；做 3 轮迭代；写复盘；把项目挂上 GitHub 或博客。
- **第 61-90 天：完成作品集与面试准备。** 第二个项目（[Lab B](/labs/lab-b-contract-review) 或 [Lab C](/labs/lab-c-knowledge-copilot)）；写一次案例复盘；三次模拟面试；开始投递。

**12 周作品集计划**（每周 6-8 小时）：

| 周 | 动作 | 产出 |
| --- | --- | --- |
| 1-2 | 补技术底座，锁定目标行业 | 学习清单 + 20 条岗位 JD 关键词 |
| 3-5 | Lab A：从基线到评测 | 可运行原型 + 评测报告 |
| 6-9 | 第二个项目 + 公开案例复盘 | 第二个项目的证据链 + 2,000 字拆解 |
| 10-12 | 一页纸、模板、三次模拟面试 | 作品集 + 简历终版 |

## 作品集：3 + 1 + 1

用最少材料证明三件事：你能独立交付、能在真实约束下拿到结果、能反思。

- **3 个项目**：至少 1 个端到端（问题 → 上线 → 指标），1 个与目标行业相关，1 个体现迁移能力。三个 [Lab](/labs/) 可直接用，但要换成完整证据链。
- **1 个案例复盘**：选一个公开案例，按「背景—问题—做法—指标—可迁移—限制」拆解，最后写「如果是我会怎么做」。
- **1 套模板**：发现访谈提纲、评测计划、上线检查表任选一套，做成可直接复用的文件。

**一页纸结构**（让陌生人 3 分钟读完）：

| 模块 | 写什么 | 常见错误 |
| --- | --- | --- |
| 一句话 | 给谁解决了什么问题，结果是什么 | 写技术栈，不写结果 |
| 问题与基线 | 现状、痛点、基线指标 | 没有数字或没有口径 |
| 方案 | 架构图 + 数据流 + 人机协作方式 | 只放截图，没有数据流 |
| 证据 | 基线 → 目标 → 实际，标样本量 | 把 demo 指标当生产数据 |
| 我的角色 | 你做的 3 个关键决策 | 把团队成果写成「我」 |
| 反思 | 最大的判断失误与改进 | 写成成功学 |
| 链接 | 代码、演示、评测集、复盘 | 链接失效或需要权限 |

托管：GitHub README 放一页纸与代码入口，博客放长复盘，简历只放链接。

<ul class="checklist">
<li>每个数字都能说出样本量、口径和时间</li>
<li>3 个项目里至少 1 个能现场演示，离线也要能跑</li>
<li>复盘里写了一个真实的失败决定</li>
<li>模板是可直接复制的文件，不是目录大纲</li>
<li>简历上每个动词后面都有结果或范围</li>
<li>能用 90 秒讲清「我为什么做 FDE」</li>
<li>准备 3 个反问：团队、客户类型、成功定义</li>
<li>所有引用和数据都标了口径，没有编造</li>
</ul>

## 简历：从「我做过」到「我交付了什么」

原则：**结果前置、范围明确、角色具体、口径诚实**。以下示例数字为虚构，请替换成你的真实证据。

**例 1：开发转 FDE**

- 改前：负责公司知识库系统开发，使用 Spring Boot 与 Elasticsearch。
- 改后：为 120 人客服团队交付内部知识检索原型，接入 3 个系统 FAQ，人工抽检 200 条问答，试点两周后一次性解决率从 41% 升到 58%（内部试点口径，样本 200 条）；本人负责检索链路、评测集与失败分析。

**例 2：咨询转 FDE**

- 改前：参与某制造企业数字化转型项目，负责需求分析和汇报材料。
- 改后：把 6 周流程诊断收敛为 1 个可运行原型，拉通 2 个车间工单数据，砍掉 3 个低价值场景，锁定「质检报告摘要」单点；用 150 份历史报告评测，摘要采纳率 72%（合成数据，样本 150 份），项目从建议推进到试点立项。

**例 3：产品转 FDE**

- 改前：负责 AI 产品规划，撰写 PRD，推动跨部门协作。
- 改后：独立实现并上线合同条款初筛工具，用 300 份公开合同构建评测集，高危条款召回率 92%、误报率 18%，法务复核时间从每份 25 分钟降到 12 分钟（内部测试，样本 60 份）；本人完成数据清洗、提示词、评测与上线检查表。

::: warning 反模式：动词堆砌
「负责、参与、推动、协同」没有信息量。改成「把 X 从 A 做到 B，覆盖 C，我的关键决策是 D」。面试官不关心你参与过什么，只关心你改变了什么。
:::

## 8 类面试题：样题、框架与扣分点

### 1. 问题拆解

**样题**：① 客户说「我们想做个 AI 客服」，你怎么判断要不要做？② 给你一张陌生业务的流程图，10 分钟找出最值得做的 AI 场景。

**框架**：现场五问（谁痛 / 痛多大 / 现在怎么解 / 为什么现在 / 谁为结果买单）→ 落到「任务—数据—决策—反馈」四要素 → 给一个两周内可验证的动作。

**扣分点**：直接讲模型和架构；不问基线；不问谁为结果负责；把「客户想做」当成「值得做」。

### 2. 客户沟通

**样题**：① 业务负责人坚持要一块「AI 大屏」，但你不认为这能解决问题；② 客户 CTO 说「数据不可能出这个门」。

**框架**：复述对方目标 → 区分立场与利益 → 给可验证的替代方案或小实验 → 把决定权交回客户 → 会后书面确认。

**扣分点**：争对错；绕过业务负责人只找 IT；为拿单承诺做不到的指标。

### 3. 技术排障

**样题**：① 上线后准确率从 85% 掉到 60%；② 客户内网接口 P99 从 800ms 涨到 5s，公网正常。

**框架**：先止血（回滚 / 降级 / 切人工）→ 分层定位（数据 / 检索 / 模型 / 链路 / 环境）→ 最小复现实验 → 记录时间线并补回归测试。

**扣分点**：上来就改提示词；没有时间线；只修现象不补测试；不向客户同步进展。

### 4. 数据

**样题**：① 客户只有 300 条标注数据，够不够？② 业务方说「我们的数据很干净」，你怎么验证？

**框架**：明确任务需要多少、什么数据 → 抽样看分布与标注一致性 → 建基线加评测集 → 给数据可用性评分与不确定性说明。

**扣分点**：说「数据越多越好」；不做人工抽检；忽略权限、脱敏与来源合法性。

### 5. 优先级

**样题**：① 三个需求同一天到期，只有你一个 FDE；② 客户要 A，你的产品团队要 B。

**框架**：价值 × 可验证性 × 依赖 × 风险四格打分 → 问「不做会怎样」→ 记录取舍、对齐干系人、给升级路径。

**扣分点**：谁嗓门大听谁的；不透明地砍需求；把冲突藏到自己扛不住。

### 6. 失败复盘

**样题**：① 讲一个你搞砸的项目；② 如果再给你一次机会，你会改哪三个决定？

**框架**：背景 → 我当时的关键判断 → 错在哪 → 后果与代价 → 我改了什么机制 → 之后的证据。

**扣分点**：把成功包装成失败；甩锅给客户或同事；只说「下次更细心」，没有机制变化。

### 7. 伦理与安全

**样题**：① 客户想用员工聊天记录训练模型；② 合同审查工具漏掉一条高危条款，谁负责？

**框架**：识别受影响的人与伤害 → 划法律与合规底线 → 最小化数据、默认拒绝 → 人工复核与可解释 → 书面风险告知。

**扣分点**：说「合规部门会处理」；为赢单降低安全标准；不会说「这个不能做」。

### 8. 业务价值

**样题**：① 客户问「这套东西能省多少钱」，你怎么算？② 试点结果很好，客户却不想续约，为什么？

**框架**：定基线 → 选口径（时间 / 人力 / 收入 / 风险）→ 归因与假设 → 给保守区间 → 用价值证据金字塔说明现在在哪一级。

**扣分点**：拍脑袋算 ROI；把 demo 指标当生产 KPI；忽略使用率与续约动机。

## 45 分钟模拟面试怎么过

| 时间 | 环节 | 你要做的事 |
| --- | --- | --- |
| 0-5 分钟 | 自我介绍 | 90 秒：我是谁 + 一个可验证结果 + 为什么做 FDE |
| 5-15 分钟 | 问题拆解 | 用现场五问，边问边写；先澄清再给结论 |
| 15-30 分钟 | 案例 / 白板 | 画现状流程 → 标数据位置 → 写基线目标 → 最小方案 → 风险 |
| 30-38 分钟 | 技术排障与数据 | 说排查顺序，不堆术语；承认不知道的部分 |
| 38-43 分钟 | 复盘 / 伦理 / 动机 | 讲真实失败；伦理题先讲底线再讲方案 |
| 43-45 分钟 | 反问 | 团队构成、客户类型、你们怎么定义成功 |

白板三条纪律：**先画现状再画方案**；**每个方案都标一个指标**；**留一条「如果不行，我们退到哪」**。

## 找工作：渠道与冷启动

- **岗位关键词**：Forward Deployed Engineer、FDE、部署工程师、AI 交付工程师、解决方案工程师、AI 应用工程师。
- **增长数据**：《金融时报》2025-11 报道 Indeed 口径 FDE 岗位九个月增长 800%（B/C，增长率，基数小）；Indeed Hiring Lab 另一口径为 2025-04 的 643 个到 2026-04 的 5,330 个（B，原始图表待核）。这是增长率，不是岗位总量。
- **内推**：优先找做过 FDE 的人。问三个问题：团队最痛的项目是什么、上一个 FDE 为什么离开、成功标准怎么定。
- **开源与社区**：给相关项目提 PR、写案例拆解、在社区做一次分享，比海投更有效。
- **培训**：上海 2025-12 启动政府主导的 FDE 培训班（据上海创智学院官网与上观新闻，B），但培训替代不了作品集。

## 薪资：只谈有来源的口径

本书不给薪资区间：可核对的中文公开数据只有一层——媒体转引招聘平台挂牌价的报道。36 氪、财联社、新浪财经 2026 年报道称 FDE「年薪百万、招聘需求涨 42 倍」（C，招聘平台挂牌价媒体汇总，单一来源簇，未披露统计地区与样本量）。挂牌价不是中位数，样本偏向一线城市头部岗位，也不含中小公司和内部转岗。

海外同理：GetPerspective《2026 FDE 薪酬报告》属单一来源，统计口径不明（C，待核）。可参照的是成本侧：SaaStr 2025-08 引用的第三方说法称，单个部署年交付成本约 7.5 万美元起，一个满负荷 FDE 只服务 3-5 个客户（C/D，第三方估算）。这说明 FDE 是高成本角色，公司会按结果而非人头付费。

你能做的三件事：查目标公司同级别岗位的公开区间；用 3 个真实 offer 交叉校准；把总包结构（base、奖金、期权、差旅补贴）问清楚。任何「学完三个月年薪百万」的承诺，都应当作招生话术。

## 拒信：最常见的六个原因

| 拒信原因 | 面试官的真实想法 | 改进动作 |
| --- | --- | --- |
| 只有 demo，没有指标 | 「他没上过生产」 | 补基线、评测集、上线后数据 |
| 讲不清自己的角色 | 「这是团队的成果」 | 写明你做的 3 个关键决策 |
| 不澄清就给方案 | 「他在背答案」 | 先问 3 个澄清问题再动手 |
| 技术不够还硬撑 | 「不敢承认边界」 | 说「这块我不熟，我会这样查」 |
| 对现场预期不符 | 「他受不了出差和客户」 | 面试前问清驻场比例与节奏 |
| 伦理与合规意识薄弱 | 「他会给公司惹麻烦」 | 准备一个「我拒绝过的需求」案例 |

::: warning 反模式：把面试当知识竞赛
FDE 面试官更在意你如何面对未知，而不是你记得多少概念。答不上来时，展示排查路径和求助方式，通常比硬编一个答案得分更高。
:::

## 本章小结

- FDE 适合愿意为结果负责、能忍受模糊的人；不适合只想写代码或只想做战略的人。
- 能力罗盘四维不必齐平，但要有一维到 L3、其余不低于 L2；只认最近 6 个月的真实证据。
- 三条路径决定你积累什么证据：产品型看抽象与反哺，伙伴型看交付治理，内部型看组织推动。
- 作品集 = 3 个项目 + 1 个案例复盘 + 1 套模板；一页纸的核心是问题、基线、证据与你的决策。
- 8 类面试题都有可练的框架；差异化来自你亲手做过的端到端项目。

## 练习

1. **写一页作品集**：按本章结构写你最强的一个项目。判断标准：陌生工程师能在 3 分钟内说出「谁痛、基线多少、你做了什么、结果多少」。
2. **录一次 5 分钟项目讲解**：手机录屏即可。判断标准：前 60 秒讲清问题与结果；能回答自己提的追问。
3. **做一次 45 分钟模拟面试**：找一位同行，从 8 类题里各抽 1 题。判断标准：记录至少 3 个扣分点，并在两周内补上证据。
4. **能力罗盘自评**：四维各选一格，写一句「我最近 6 个月的证据是什么」。判断标准：写不出证据的维度，主动降一级。
